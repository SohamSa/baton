# Implementation contract

Baton is a new repository. It is not a branch or copy of any earlier project. The product is a research application whose subject is a GPU cluster of 32,768 accelerators. It is not a branch or copy of any earlier project. Detailed device physics covers the placed ranks. The remaining accelerators are the quiescent population of the same cluster. The process does not attach to those accelerators.

## Boundaries

- No real fleet telemetry, physical GPU control, paid APIs, or public deployment in this build.
- No default currency rates, ROI headline, or externally attributed fleet statistics.
- Fictional organizations and hardware families only.
- Symptoms are separate from causes. Unknown, conflicting evidence, and abstention are valid outcomes.
- The backend is authoritative. The web application renders and requests actions.
- Hardware adapters stay disconnected. Model output cannot run a shell or reset a device.
- High-impact manual actions require an authenticated approver. Automated experiments are labeled automated policy decisions.
- A trained model replaces the rule policy only when it improves held-out decision utility. The checked artifact does not, and the rule policy remains the default.
- Private simulator truth is evaluator-only.

## Gates

1. Foundation: independent repo, lockfile, schema, health, dictionary.
2. Core world: deterministic synthetic world, strict synchronization, checkpoints, ledger.
3. Decision path: features, incidents, approvals, API, connected UI.
4. Rich data: catalog coverage, heterogeneous stories, resumable Parquet.
5. Learned intelligence: trained artifact, calibration note, honest baseline comparison.
6. Policy experiments: paired worlds, negative result, economics disabled by default.
7. Product: required views, guided stories, presentation mode, roles, audit, tests, and docs.

## Acceptance claim

The software may claim that it is a reproducible synthetic environment for studying those questions. Stronger claims about production reliability or monetary return are out of scope until a separate real-data pilot says otherwise.

Detailed behavior is specified in `docs/` and enforced by `tests/`. `IMPLEMENTATION_STATUS.md` records what was actually run.
